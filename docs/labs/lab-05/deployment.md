## 1. Stack and changes from the reference kit

| Part | What we use |
|---|---|
| App | React 18 client (Vite) + Express 4 API on Node 24, Prisma 5 ORM, PostgreSQL 17 |
| Container | One image from the root `Dockerfile`: client build, server build, then a slim Node 24 runtime that serves the API and the built client on port 3000 as the non-root `node` user |
| Compute | Cloud Run service `adviseslot` (scales to zero) |
| Database | Cloud SQL for PostgreSQL 17, connected through the Cloud SQL unix socket |
| Secrets | Secret Manager |
| Images | Artifact Registry |
| CI/CD | GitHub Actions: `ci-docker.yml` (job `test-and-docker`) on every PR into `sprint-1` and `main`; `deploy.yml` on every push to `main`, logging in to GCP with Workload Identity Federation (no key file) |

Changes from the Lab 5 starter kit (TokTickIT):

- Resource names use `adviseslot` instead of `toktickit`.
- PostgreSQL **17** instead of 16, the same major version as local development (D-25).
- No admin password: AdviseSlot has no admin account. Instead the seed needs `SEED_DEMO_PASSWORD` for its demo accounts; `deploy/deploy.sh` generates it into Secret Manager.
- The migrate job runs `npx prisma migrate deploy && npx prisma db seed`.
- `deploy/smoke_test.py` checks our API: `/api/ready` returns `"db": "up"`, the session is the `sid` cookie (not a bearer token), and `/api/slots/bookable` must answer 401 when logged out. It also checks that `/api/version` reports the commit just released.
- Extra: `deploy/setup-wif.sh` scripts the Workload Identity Federation setup that the kit describes in `docs/auto-deploy.md`, and `deploy/teardown.sh` also removes it.
- Extra: the page footer and `GET /api/version` show the running commit (#50).

## 2. Environment variables

No real value of a secret is in Git, the image, logs or the PDF. Local values come from `server/.env` (copied from `server/.env.example`, placeholders only) and are never committed.

### Application (server)

| Variable | Purpose | Secret? | Local value from | On Cloud Run from |
|---|---|---|---|---|
| `DATABASE_URL` | PostgreSQL connection string for Prisma | **Yes** | `server/.env` (local Docker database only) | Secret Manager `adviseslot-database-url`, mounted into the service and the migrate job. Generated by `deploy.sh`; uses the Cloud SQL socket `/cloudsql/adviseslot:asia-southeast1:adviseslot-pg` |
| `SEED_DEMO_PASSWORD` | Password the seed gives the demo accounts (12+ characters; the seed refuses to run without it) | **Yes** | `server/.env`, `server/.env.test` | Secret Manager `adviseslot-demo-password`, mounted into the **migrate job only**, not the service. Generated by `deploy.sh` |
| `NODE_ENV` | `production` turns on serving the built client and the `Secure` session cookie | No | `server/.env` (`development`), Dockerfile (`production`) | Set by `deploy.sh` (`production`) |
| `PORT` | Port Express listens on | No | `server/.env` (`3000`) | Dockerfile default `3000`; Cloud Run sends traffic to port 3000 |
| `CLIENT_ORIGIN` | Allowed CORS origin for the Vite dev server | No | `server/.env` (`http://localhost:5173`) | Not set: in production the client is served from the same origin, so CORS is not needed |
| `CLIENT_DIST` | Optional path of the built client | No | Not set | Not set; the default `/app/client/dist` in the image is used |
| `APP_COMMIT` | Commit SHA shown by `/api/version` and the footer | No (public, the repository is public) | Not set, so it shows `dev` | Set by `deploy/release.sh` to the released image tag (the commit SHA) |
| `TZ`, `APP_TIMEZONE` | Time zone `Asia/Bangkok`. The code formats times explicitly, so these do not change behaviour | No | `server/.env` | Set by `deploy.sh` |

### First-time setup (already done, #42 and #44)

From the repository root in Cloud Shell, as a project Owner. Each script has a dry run that prints the commands and creates nothing; read it first.

```bash
DRY_RUN=1 PROJECT_ID=adviseslot bash deploy/deploy.sh
PROJECT_ID=adviseslot bash deploy/deploy.sh

DRY_RUN=1 PROJECT_ID=adviseslot bash deploy/setup-wif.sh
PROJECT_ID=adviseslot bash deploy/setup-wif.sh
```

Both are safe to re-run: what exists is reused, and credentials are never replaced. New service accounts and pools take a few minutes to become visible, so a first run may stop with "does not exist" or "permission denied"; wait and run the same script again. Read the demo password yourself with `gcloud secrets versions access latest --secret=adviseslot-demo-password` and never paste it anywhere.

### Cost control and teardown

Cloud SQL is billed per hour even when nobody uses the site (about ฿16 to 21 a day). Cloud Run scales to zero and costs almost nothing when idle. Stop the database when the site is not needed and start it before a demo or grading; the data is kept, and the site returns errors while it is stopped:

```bash
gcloud sql instances patch adviseslot-pg --activation-policy=NEVER --project adviseslot    # stop
gcloud sql instances patch adviseslot-pg --activation-policy=ALWAYS --project adviseslot   # start
```

Keep the service running until the instructor announces the end of grading. Then preview and run the teardown, which asks you to type the project ID, and check in the Console that nothing is left (SQL, Cloud Run services and jobs, Artifact Registry, Secret Manager):

```bash
DRY_RUN=1 PROJECT_ID=adviseslot bash deploy/teardown.sh
PROJECT_ID=adviseslot bash deploy/teardown.sh
```
